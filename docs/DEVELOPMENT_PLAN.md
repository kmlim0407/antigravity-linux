## 부록: 시니컬한 비평

### "계획은 많고, 할 시간은 없다"

개발계획서는 멋지다. Phase 4까지 써놨지만, 현실은 **학원 운영**이 메인이고 코딩은 취미에 가깝다. 학생 5명 명단을 하드코딩해놓고 "PostgreSQL 도입 검토"를 쓰는 건, 아파트 한 채도 없는 사람이 부동산 포트폴리오 전략을 세우는 수준이다.

### "Notion에 다 묶어놓고 Notion 이탈을 검토한다"

데이터가 전부 Notion에 묶여 있다. API 한도, 스키마 변경, 속도 제한—전부 Notion 손바닥 위다. 그런데 Phase 4에서 "Notion 의존도 완화"를 쓰는 건, 이미 결혼해놓고 "이혼 가능성 검토"를 미래 과제로 남겨두는 것과 비슷하다. 당장은 못 빠져나올 거다.

### "학생 비밀번호 1234를 평문으로 번들에 넣어놨다"

`lib/students.ts`를 열면 김지호 비밀번호 1234가 그대로 보인다. 해시도 아니고, env도 아니고, **클라이언트 번들**에 박혀 있다. "Phase 2에서 해시 검토"라고 써놨지만, 그전에 누가 코드만 퍼가도 명단+비밀번호 전부 털린다. 보안은 나중 문제가 아니다.

### "성취도를 localStorage에 저장한다"

학생이 "저장됨 (기기별)" 메시지를 보고 만족할 수 있을까. 핸드폰 바꾸면? 브라우저 데이터 지우면? 선생님은 그 데이터를 **절대 못 본다**. "데이터 기반 수업 설계"를 홍보해놓고, 실제 기반 데이터는 학생 기기 메모리에 갇혀 있다. 아이러니하다.

### "[i.d] 라우트 오타"

Next.js 동적 라우트는 `[id]`인데 `[i.d]`로 만들어뒀다. 오타 한 글자가 학생 상세 페이지를 망가뜨릴 수 있는데, 개발계획서 Phase 1에 넣어놨다. **그냥 지금 고쳐라.** 2분이면 된다.

### "1인 개발인데 Phase 4까지 있다"

Phase 4에 "AI 활용 문제 추천", "React Native", "결제·수강료 관리"가 있다. 1인 개발자가 학원 운영하면서 이걸 다 한다고? 현실적으로 Phase 1 버그 수정 + Phase 2 성취도/학생관리 실제 연동만 해도 몇 달 걸린다. 나머지는 "하고 싶은 것 목록"에 가깝다.

### 결론

계획서는 **방향**을 제시하는 데는 좋다. 하지만 "할 일"보다 "하지 말아야 할 일"을 먼저 정리하는 게 낫다.  
— 지금 당장: `[i.d]` 고치고, Debug 배너 빼고, 비밀번호라도 env로 옮겨라.  
— 그다음: 성취도를 Notion에라도 저장해서 선생님이 볼 수 있게 하라.  
— 나머지는 그때 그때.

*"완벽한 계획보다 털썩 움직이는 한 걸음이 낫다"* — 누가 말했는지는 모르겠지만, 여기엔 딱 맞는 말이다.
